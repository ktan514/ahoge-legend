# アホ毛の接触表示・画面内配置

関連: #102 / PR #105。2026-10-04の実機録画への修正。
`AHOGE_MESH_DEFORMATION_DESIGN.md` / `AHOGE_MESH_IMPLEMENTATION.md` の追加仕様。本書は全体運動を無補正で維持する制限より優先する。

## 不具合と目的

録画では、直線化が完了しても毛先が上方を向き、相手へ届かないままHITが表示された。溜めでは頭部が左端から欠けた。
形状値が1であることは接触成立の証拠ではない。既存の固定メッシュ・形状キー・UVを維持し、表示座標上の毛先と相手の頭部を同じ時刻に合わせる。

## 責務

- 既存FighterVisualとAhogePrototypeRigは単体描画・全体運動の基準として残す。
- BattleFighterVisualはFighterVisualを継承し、画面内の頭部運動と接触表示を担当する。BattleHUDでのみ採用する。
- BattleContactDirectorは両頭部の更新後に接触表示を確定する。左右の処理順に依存させない。
- 頭部→アホ毛の更新を各frameで1回だけ実行する。
- serverの状態・Hit・Contact・Rating・切断処理を変更しない。表示からゲーム判定を書き換えない。

## 接触目標

相手の頭部画像のalpha輪郭から、攻撃側に近い上側の接触点を初回読込時に取得し、頭部transformで現在の画面座標へ変換する。未素材の相手では実際に描いている頭部円の上側輪郭を用いる。
描画メッシュのcurrent_verticesの最終頂点を毛先として使う。別の仮想tipを検証対象にしない。

接触予定時刻まで、既存のStraightenと同じ進行量で表示補正を増やす。既存MotionRootを出発点に、毛先の向きを目標へ回し、根元→先端方向の不足分だけ拡縮する。垂直な幅方向へ新たな射程倍率を掛けない。
接触時にはStraighten=1、目標への毛先誤差2px以下を検査する。補正は根元を動かさない。戻りも直線化と同じ進行量で補正を解く。

オンラインのhit_confirmedを受けたframeにも実際の接触姿勢を提示する。これは既に確定した結果の表示であり新しい攻撃ではない。同一イベントは重複表示せず、無関係な参加者・非表示状態・新しい攻撃に入った後の古いイベントを受け付けない。Round lock・防御中断から古い攻撃を再生しない。
DODGE中の相手には目標追従を停止し、回避した相手へ追尾する表示を避ける。

### フレーム間の基準変換の独立性

接触補正は根元→先端軸に沿う非等方伸縮を含む。その合成行列にはskew（せん断）が生じ得る。これは当該frameの表示結果であり、次frameの基準運動へ入力してはならない。

AhogePrototypeRigは毎frame、保存したwhole angle、whole reach、base scale、vertical squashだけからMotionRootのTransform2D全体を再構築する。基準変換のskewは0、local originは0とする。Node2Dのrotationとscaleだけの更新では既存skewが残るため、その更新方式は使用しない。

BattleFighterVisualはこの新しい基準変換を保存してから、当該frameの接触・画面内補正を適用する。補正後の最終transformにskewがあること自体は不具合ではない。前frameのskewが新しい基準へ混ざることを禁止する。同じframeで同じ目標へ再提示しても補正を累積しない。

この修正のためにPNG、断面、UV、固定三角形、形状キー、接触位置、全体運動の係数、サーバー判定を変更しない。太さを任意の倍率で水増しして細線化を隠さない。

## 見切れ防止

頭部モーションの時間曲線は保持し、後退は最大36px、前進は最大28pxを基準とする。実画像のalpha範囲と頭部回転から計算した横幅が、Battle表示領域からはみ出す場合はさらに変位を制限する。補正後の頭部位置から速度・加速度を求める。
頭部の下端cropは維持する。アホ毛は頭部clipの外側に置く。
Battle表示領域には共通clipを設定するが、それだけで見切れ修正済みとは判定しない。補正後の全メッシュ頂点が表示領域内かを検証する。HUD侵入を避ける最後の保護として、根元を固定して領域内へ収まる表示倍率を求める。接触時に保護倍率で射程が短くなる場合は検査NGとする。

## 検証

実際のBattleHUDへLONGと相手を配置し、通常0.20秒と最大チャージ0.13秒を使用する。左右、30/60/120fps、1280x720と1600x900を検査する。

- 接触予定時刻のStraighten、実メッシュ最先端と相手のalpha接触点との距離。
- 溜め・攻撃・戻り・パリィ中断中の頭部横端と全メッシュ頂点の画面内包含。
- Contact補正による根元のずれ。
- 明示Hit通知の表示、重複・非表示・防御中断からの再発防止。
- Godot描画画像と通常速度の連続frame。画像が生成されたことだけで見た目PASSとはしない。
- 既存の幾何学検査、単体試験、オンライン回帰も維持する。
- MotionRootへ前frameのskew・originを与えたリグと、与えない対照リグを同一入力で進める。新しい基準の全transformと描画頂点が一致すること。
- 実Battleの基準変換の直交性と行列式、中央断面の画面上の幅を記録する。単にメッシュ頂点間距離を測るだけでなく、中心線へ直交する投影幅を測る。
- 同一frameの再提示、連続攻撃・復帰でも歪みが蓄積しないこと。

### 描画試験の寸法契約

BattleHUDのFULL_RECT anchorは親の寸法を参照する。試験用SubViewportへ追加する前にHUDへ解像度をsizeとして設定し、親の幅・高さとoffsetを二重加算してはならない。親へ追加した後にanchorとoffsetをFULL_RECTへ揃える。

配置確定後、HUDの原点・寸法がSubViewportと一致し、BattleArea全体がその描画範囲内にあることを先に検査する。不一致の場合は当該条件を失敗として記録し、接触検査へ進まない。
接触点はキャプチャ画像内にあることを明示検査する。画面外の空の画素範囲を「毛先が描かれていない」という結果に混同しない。48条件と毛先誤差2px以下・接触点近傍の描画差という合格基準は維持する。
