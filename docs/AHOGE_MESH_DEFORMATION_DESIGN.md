## 2. 要求と変更しないもの

### 2.1 要求

人間さんの要望は、アホ毛が伸びる際に、中央だけでなく**実際の毛先の先端まで真っ直ぐに近づく**こと。そのために三角メッシュを使い、Live2Dのように形状を変えたい、というものである。

採用する構成は「元プロトタイプ由来の全体運動 + アホ毛専用の形状変化」。3D制作、汎用リグ編集画面、Live2D Cubism SDKの導入は今回の必須条件にしない。

### 2.2 維持するもの

- 頭部・髪・UIは2Dのまま。
- 頭部運動から速度・加速度を取り、アホ毛の全体角度・reachを追従させる既存処理。
- 通常攻撃とチャージ攻撃の違い、ばねと減衰による遅れ・振り戻し。
- 頭部とアホ毛はキャラクター固定セット。付け替え機能は追加しない。
- 通常GameFlowからBattleへ入る。専用Battle直行起動は追加しない。
- SHORT_TESTの未素材時の描画と既存投擲処理。
- NakamaのContact / Hit / Defense / Round / Match / Rating判定。
- 両者切断時の無効試合と、片側切断時の既存再接続仕様。

## 4. メッシュの作り方

### 4.1 画像の高さではなく、毛束に沿って番号を付ける

C字のアホ毛では、画像の最上端と毛先は一致しない。毛束は上へ進んだ後に折り返す。同じY座標に、根元側と毛先側の別の場所が現れ得る。

そのため、横一列のalpha最小X・最大Xを1本の断面とみなす方法を採用しない。これは離れた二つの毛束部分や透明な空間を一緒に扱う可能性があり、根元から毛先への対応を保証しない。

現行画像を見ながら、根元からカーブを回り込んで本当の毛先へ至る中心線を指定する。その線に沿った距離を `s=0..1` とし、`s=1` を毛先とする。初期データ作成はチャッピー側の制作作業とし、人間さんに新しい3Dモデルや描き直し素材を要求しない。

### 4.2 固定するデータ

- 頂点数、頂点ID、三角形のindex、UV。
- 元画像上の各頂点位置と、毛束に沿った位置s。
- 根元anchorと、先端を表す頂点ID。
- 形状キーごとの、同一頂点IDに対応する位置。

隣接する面は同じ頂点IDを共有する。面ごとに独立した境界頂点を動かして継ぎ目を作らない。必要な内側頂点を置き、透明なC字の内側を横断する面を自動的に張らない。

毛先は先端専用の頂点と三角形の扇で閉じる。同一点へ左右頂点を重複配置した面積0の面で閉じない。

### 4.3 待機形状の互換性

変形量0の頂点位置は、元PNG座標から根元anchorを引いた位置そのものとする。中心線のnormalへ機械的に並べ直した位置を待機形状にしない。

UVは元画像上の座標に対応させる。MeshInstance2Dの描画では0..1のUVとして保存する。輪郭のサンプリング余白、texture filter、alpha境界も含めて元Spriteとの描画差を確認する。

この段階で元画像と違って見える場合、攻撃変形の作業へ進まない。

## 5. 形状パラメータ

| 項目 | 担当 | 初期仕様 |
| --- | --- | --- |
| Swing | 既存の全体運動 | 既存whole angleを維持 |
| Reach | 既存の全体運動 | 既存whole reachを維持。新しい倍率を二重加算しない |
| Straighten | 新規メッシュ変形 | 0で元画像、1で中央から実際の毛先まで直線に近づける |
| TipHook | 初回実装では無効 | 0固定。毛先のフックを勝手に追加しない |

根元の接続点は全形状キーで同じ位置に固定する。根元付近に少量の曲がりを残しても、毛先側の折り返しはStraighten=1で解消する。

Straighten=1は画像の縦方向を押し潰す操作ではない。カーブをほどき、中央から先端まで同じ前方へ向くように各頂点を移動する操作である。

輪郭の太さとハイライトを数学的に完全不変にはできない。毛束を横切る方向の幅を制御し、元の絵の特徴を保てているかは描画で検証する。

## 6. 形状キーと補間

### 6.1 初期のキー

Straighten `0 / 0.25 / 0.5 / 0.75 / 1` の5形状を初期案とする。数は見た目と検査結果で増減できる。

- 0: 元のC字。
- 0.25〜0.75: 先端の折り返しを段階的にほどく中間形状。
- 1: 根元側の短い移行区間を除き、中央から先端まで前方へ揃う形状。

制作時には中心線の向きが連続して変わるように中間形状を作る。始点と終点だけを用意して、長いカーブを無検証で一直線に補間しない。

### 6.2 実行時

Straighten値を挟む2個のキーの同一頂点を補間する。

```text
local_vertex[i] = lerp(key_a[i], key_b[i], weight)
表示位置 = 頭頂部anchor + 左右反転 * 既存MotionRoot変換 * local_vertex[i]
```

UVと三角形indexは変えない。変形量0では既存の全体運動だけの描画と一致させる。

Straighten形状はカーブをほどく役割に限定し、既存Reachの2倍相当の伸長をさらに形状キーへ重複して入れない。最終的な到達位置・太さは、非等方なReach拡縮まで適用した画面上で測る。

## 7. 時間制御と頭部への接続

### 7.1 時間制御

- IDLE / CHARGING / WINDUPではStraighten=0を基本とし、まず既存の大きな動きを維持する。
- STRIKEの展開区間でStraightenを増やし、Contact付近では先端までほどけた形を目標とする。
- COOLDOWNでは遷移時の変形量から0へ戻す。状態が変わった瞬間にC字へ飛ばさない。
- PARRY / DODGE / STAGGERへ中断された場合も現在形状を保持してから短く復帰させ、攻撃の伸長姿勢を再発させない。
- ROUND_LOCKED / 非表示 / 再接続時には過去の攻撃を勝手に再生しない。

Straightenの時間軸は、利用可能なauthoritativeのstrike開始・Contact時刻、またはそれに同期した既存の状態進行から得る。見た目のためにserverの攻撃時間やHit判定を変更しない。

`whole_reach`はばねで遅れるため、その値だけを使ってStraightenを駆動すると、実際のSTRIKE終了後にしか先端が伸びない可能性がある。状態進行と合わせて評価する。

0.4秒以上STRIKEを強制維持する試験だけで、実際の短いSTRIKE中の到達を確認したことにしない。通常・最大チャージの実時間で評価する。

### 7.2 根元

頭部の移動・回転・拡縮・左右反転を適用した頭頂部の位置へアホ毛anchorを接続する。形状変化の固定点はこのanchorと一致させる。

元画像の根元座標と頭部側の接続座標は別のデータとして保持する。画像サイズだけの比例変換で両者が一致すると仮定しない。

確認対象には、攻撃だけでなくパリィ時の大きな上下移動も含める。下端の頭部cropは維持し、アホ毛を頭部専用clipの子に入れない。

## 8. Godot実装単位

以下の新規ファイル名は予定であり、まだ作成済みではない。

| ファイル | 責務 |
| --- | --- |
| `src/ui/ahoge_prototype_rig.gd` | 既存。全体運動の式と状態を維持し、Spriteまたはメッシュ描画へ同じMotionRoot変換を渡す |
| `src/ui/ahoge_mesh_profile.gd` | 新規予定。素材識別、anchor、固定UV/index、形状キーと検証情報を保持するResource |
| `src/ui/ahoge_mesh_deformer.gd` | 新規予定。Straightenから頂点位置を求め、描画へ渡す。勝敗判定を持たない |
| `assets/characters/prototype/charactor_01/ahoge_mesh_profile.tres` | 新規予定。現行LONG画像に合わせて制作・検証したデータ |
| `tests/ahoge_mesh_geometry_test.gd` | 新規予定。形状補間と固定データの検査 |
| `tests/ahoge_mesh_render_test.gd` | 新規予定。実SceneTree・描画バックエンド上の比較と攻撃cycle確認 |

描画案:

```text
FighterVisual
├─ HeadClipControl
│  └─ HeadSprite
└─ AhogePrototypeRig
   └─ AhogeMotionRoot
      ├─ AhogeSprite（移行中の比較・異常時のfallback）
      └─ AhogeMeshInstance（MeshInstance2D + ArrayMesh）
```

通常表示はどちらか一方だけにする。二重描画で濃く見える状態を作らない。

ArrayMeshは明示triangle indexで初期化する。実行時は頂点領域のみを更新する方針とし、UV/indexの再生成、毎frameの輪郭抽出、自動triangulationは行わない。`surface_update_vertex_region`を使う際は対象Godot版の頂点形式・byte配列・描画結果を単体で確認する。未検証のstrideを埋め込まない。

カリング用の表示範囲は全形状キーを包含する。データ不一致や異常形状を検知した場合は元Spriteへ戻し、開発用logには理由を残す。fallbackで表示が残ったことを、メッシュ試験PASSにはしない。

最低限、次をResourceへ保持する。

全形状キーで頂点IDは同一でなければならない。素材差し替えで寸法やdigestが変わった場合、古いメッシュをそのまま使わず再確認する。

同じY座標かどうかではなく、毛束に沿うsと幅方向の位置で各頂点を対応付ける。曲がりが強い部分と先端に頂点を増やす。初期の分割数は試作で決め、数を増やしたこと自体を品質保証にしない。

## 10. 破綻を防ぐ検証

### 10.1 固定接続だけでは足りない

固定indexと固定UVでも、頂点の動かし方によって三角形は潰れたり反転したりする。始点と終点が正常でも補間途中が正常とは限らない。

したがって「固定三角メッシュだから裂けない・消えない」という説明だけで採用しない。

### 10.2 幾何学検査

- 頂点数・UV数・index範囲・値の有限性。
- 全shape keyでroot固定、同一頂点ID、同一接続。
- 退化した三角形、非共有の継ぎ目、意図しない内部境界がない。
- 各補間区間で三角形の符号付き面積が0にならず、向きが反転しない。
- 線形頂点補間の面積は補間係数の2次式として扱い、区間端と区間内の極値を検査する。離散サンプルだけで区間全体を保証したことにしない。
- 非隣接の面や輪郭の重なりも別途検査する。面積検査だけで自己交差なしとは判定しない。
- 左右反転は全体変換として扱い、片側だけの反転を局所メッシュ破綻と混同しない。

### 10.3 描画検査

変形量0を元Spriteと同じ位置・scale・filterで比較する。輪郭欠け、透明な穴、根元のずれ、色の二重化がないことを確認する。

Straightenの全キーと中間値を描画し、通常攻撃・最大チャージ・パリィ中断・再接続を含むcycleを確認する。Nodeが存在すること、頂点数が正しいことだけでは描画PASSにしない。

実際に表示された毛先を検査する。補助関数が計算した仮想的なtipだけを測って、描画上の先端が届いたことにしない。

### 10.4 初期の数値判定案

次は実装時に測定して調整する試験基準案であり、達成済みの値ではない。

- 基準1280x720で、変形によるroot位置のずれを1px以内にする。
- Straighten=1で毛先側20%の中心線の向きが、目標の直線方向から5度以内に収まることを初期目標とする。
- 中央部の画面上の断面幅を計測し、同じ全体運動・scaleを適用した変形量0との比が0.7未満へ落ちる箇所は要確認とする。先細りする最終端は除く。
- restのalpha輪郭比較、攻撃中の面積・幅・先端軌道を記録する。数値が通っても見た目がNGなら不合格。

30 / 60 / 120fps、左右配置、通常解像度と拡縮表示を対象にする。対応rendererごとの実描画を確認し、headlessのみの成功を実機表示の保証にしない。

## 11. 実装順序と停止条件

1. 現行素材のroot・tip・曲線に沿った固定メッシュを作成する。Straighten=0で元Spriteと比較する。
2. 形状キーを制作し、全補間区間の幾何学・描画検査を行う。
3. 元の全体運動を保ったまま、STRIKE時のStraightenを接続する。実際の攻撃時間で確認する。
4. 通常GameFlowでHuman Verificationを行う。毛先の直線化、太さ、戻り、頭部接続を確認する。

前段がNGなら次段へ進まない。既存Spriteを先に削除して、再び何も見えない状態で人間さんへ確認を依頼しない。

今回の完成条件は、方式の名前やテスト件数ではなく「元の気持ちよい全体運動を保ち、伸長時には実際の毛先までほどけ、絵が連続して見える」こととする。
