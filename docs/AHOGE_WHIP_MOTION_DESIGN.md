# アホ毛の溜め・ムチ打ち・パリィのモーション見直し

関連: #102 / PR #105
基準コード: `8f04cbfeb53c7581635c78113eb7bfcabd81455e`

## 1. 要求と現在地

人間さんからの追加要求:

- チャージで後ろへ引く際に、アホ毛がもっと後ろへ垂れるように形状変化する。
- 前方攻撃は、相手をムチで叩くような動きにする。
- パリィの動きは全面的に見直す。

本書は追加要求の設計案であり、変更後の製品コード・実描画の完了記録ではない。特にパリィの具体的な払い方向は提案であり、承認済みの方向として扱わない。
添付 `名称未設定(6).mov` は受領したが、今回の作業環境では動画の再生・フレーム抽出に成功していない。観察した時刻や動画からの所見は本書へ記載しない。要求の根拠は上記の人間さんの文章、現状の根拠は基準コードおよび既存設計とする。

現状:

- 固定三角メッシュに待機C字から直線へほどく形状がある。
- `AhogeMeshMotion` はSTRIKEの直線化と中断後の復帰を制御する。CHARGING専用の後方へ垂れる形状はない。
- Battle側には接触点へ向き・距離を合わせる補正がある。これは見た目の接触を支えるが、それ自体はムチ打ちの軌道設計ではない。
- 基本設計 §7.1はパリィを能動的な払い上げ／はたき落としとし、頭部の上下切り返しからアホ毛へ動きを伝える。

## 2. 維持する構造と非対象

2D頭部画像・現行アホ毛PNG・毛束に沿う固定UVと三角形接続を維持する。3D化や新しいボーン方式への全面置換は行わない。

`AHOGE_CONTACT_PRESENTATION.md` の根元固定、頭部とアホ毛の一回更新、基準Transform2Dの独立再構築、細線化防止、画面内配置は維持する。

server authoritativeなHit / Defense / Just / Clash / Round / Match / Rating、切断・復帰仕様を変更しない。SHORT投擲をLONGのムチ打ちへ置換しない。アホ毛不在中の右クリックは従来どおりDODGEとする。

ここで追加するのは表示モーション。相手への接触時刻だけを維持して、以前の全体回転・伸長係数の完全一致は変更後の合格条件にしない。元prototypeの頭部先行・遅れ・勢いは参照として残す。

## 3. チャージ: 後方へ垂れる形状

C字の画像全体を後方回転するだけでは要求を満たさない。根元・中間部・毛先の相対位置も変える。

流れ:

1. 頭部が小さく後退し、根元が頭頂部について動く。
2. 中間部が遅れて後方へたわむ。
3. 毛先側がさらに遅れて後方・下方へ落ち、柔らかく垂れた形になる。
4. 長押し保持中はその形で落ち着く。揺れ続けたり、時間とともに巨大化したりしない。

形状パラメータ案 `HangBack`: 0で元のC字、1で後方へ垂れた最大溜め姿勢。実際のチャージ経過に合わせて推移させ、頭部由来の遅れを重ねる。

後方とは各キャラクターのfacingに対する後方とする。毛先は中間部より下へ向かい、先端接線が後方・下方を向く形を目標とする。根元まで寝かせたり、頭部にめり込ませたりしない。

チャージ中に追加の射程伸長はしない。後方の余白を超える場合は、最初から表示領域内で成立する溜め形状と配置を調整する。全体縮小だけで見切れを隠して合格にしない。

## 4. 攻撃: しなりを伝えて叩く

目標は、直線化した毛を相手へ突き出す動作ではなく、たわみが根元から毛先へ移動し、最後に先端が加速して叩く動作。

基準形状の案:

- `BackHang`: 溜めの後方へ垂れた形。
- `RootLead`: 頭部と根元が前進しても毛先は後ろへ残る。
- `MidArc`: 中間部が前方の大きな弧になり、毛先はその後ろに遅れる。
- `TipRelease`: たわみが毛先へ移動し、巻き込みがほどける。
- `Contact`: 先端まで伸びた毛束が相手へ接触する。
- `FollowThrough`: 接触後にしなりが反転し、振り戻しへ移る。
- `Rest`: 元のC字へ収束する。

形状を単に等時間で切り替えず、根元・中間・先端の前方速度のピークをこの順にずらす。細かな振動を多重に加えるより、一本の大きなしなりが伝わる見え方を優先する。

接触予定時刻には、従来要求どおり先端の巻き込みまでほどける。実メッシュ先端と相手の表示位置の誤差2px以下、塗りと幅の保持を維持する。ただし接触後も相手に先端を貼り付けて保持しない。接触前後の短い区間でのみ必要な到達補正を強くし、振り抜きと復帰では解除する案とする。

通常STRIKE 0.20秒、最大チャージSTRIKE 0.13秒、contact_ratio 0.70という基準コードの時間内で検証する。演出を見せるためにserverの攻撃時間や判定時刻を伸ばさない。authoritativeイベントを基準にした実表示との同期は維持する。

チャージ解放時にC字へ一度戻してから攻撃しない。解放した時点のHangBackと速度から攻撃軌道へ接続する。

## 5. パリィ: 動作全体の再設計案

人間さんからは全面見直しが要求されているが、払い方向までは指定されていない。第一案は、前方の短い範囲で相手のアホ毛を上から斜め下へはたき落とす動作とする。払い上げへ変更する余地を残す。

第一案の流れ:

1. 小さな頭部の上下切り返しで、根元から中間部を前上方へ立ち上げる。
2. 頭部の下向き切り返しに遅れて先端が追従し、前方の短い弧を一度だけ素早く払う。
3. 相手の攻撃アホ毛を叩いた位置で跳ね返り、短い余韻で戻る。

攻撃は相手頭部への長いムチ打ち、パリィは自分の前方で攻撃アホ毛を払う短い迎撃として区別する。相手の頭部をパリィの到達目標にしない。頭部の大きな上下ジャンプや全体回転だけで形を作らない。

PARRY / JUST_PARRYの成否はserver結果を使用する。成功通知なしに相手を弾いた演出を確定しない。JUST時の強調・相手の仰け反りは既存結果に従い、新しいダメージや判定受付時間を追加しない。

基準PARRY有効時間0.18秒、Just受付0.07秒を保持する。長い溜め演出を新設して防御開始を遅らせない。描画上の余韻と防御有効時間を分離する。

CHARGING / WINDUP / STRIKEのどこから中断しても現在の形・速度からパリィへ遷移する。いったんC字へ飛ぶ、古い攻撃接触を再生する、形状が突然反転する遷移は不合格とする。

## 6. 実装方針

- 形状データ: 既存profileの固定トポロジーへ後方垂れ・ムチの途中形・パリィ専用形を追加する。PNGの高さで再走査したメッシュへ戻さない。
- 動作制御: `AhogeMeshMotion` 相当の責務を、単一Straightenからアクション別の段階・現在形状・復帰へ拡張する。HangBackとStraightenを無条件に加算しない。
- 頭部: 小さい頭部移動を駆動源とし、後退量を増やすだけの代用をしない。
- 接触表示: `BattleContactDirector` 側で攻撃用と防御用の表示目標を分離し、回避した相手を追尾しない。基準transformと当該frameの補正transformを混同しない。
- 操作: 通常GameFlowで動作させる。専用Battle直行画面や独立装備は追加しない。

形状を増やすだけで途中の面が保証されるわけではない。採用する遷移経路ごとに面積・外周・実描画を検証する。滑らかな見た目のために既存の判定やテストしきい値を緩めない。

## 7. 完了条件

- 溜め中、頭部相対で毛先が後方かつ下方へ垂れ、実際の形が変わる。チャージ中の全長が不必要に増えない。
- 根元、中間部、先端の前方加速に順序があり、等倍再生でムチ打ちに見える。
- 通常・最大チャージの実時間内で、巻き込みをほどいた実毛先が接触位置へ届く。
- 接触後に先端が相手へ貼り付かず、振り戻しへ連続する。
- パリィは攻撃とは違う短い軌道で、相手のアホ毛を迎撃するように見える。
- 左右・相手LONG/SHORT・30/60/120fps・1280x720/1600x900、低チャージから最大チャージ、長押し保持、中断を検査する。
- 固定UV/index、太さ、根元、見切れ防止、歪み蓄積防止の既存回帰を維持する。
- 実描画の等倍動画を主に、スローと時系列画像を補助として比較する。旧48条件PASSを新モーションの見た目PASSへ流用しない。
- Mac通常GameFlowのHuman Verificationと独立レビューを経る。未確認でPR #105をマージしない。
