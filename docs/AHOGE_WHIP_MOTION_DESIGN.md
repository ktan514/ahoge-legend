# アホ毛の溜め・ムチ打ち・パリィのモーション見直し

関連: #102 / PR #105
基準コード: `8f04cbfeb53c7581635c78113eb7bfcabd81455e`

## 1. 要求と現在地

人間さんからの追加要求:

- チャージで後ろへ引く際に、アホ毛がもっと後ろへ垂れるように形状変化する。
- 前方攻撃は、相手をムチで叩くような動きにする。
- パリィは曲がった状態を保ち、近距離で先端部分だけが相手の攻撃を払い除ける。

今回の承認により、パリィを全体の振り上げ／はたき落としで作る旧案は不採用とする。先端部分とは最先端の一点ではなく、その手前を含む短い毛束である。
本書は設計の正本であり、実装・実描画・Human Verificationの成功を意味しない。
添付動画について再生できていない区間の所見を作らない。要求の根拠は人間さんの文章、現状の根拠は基準コードと既存設計とする。

現状の固定三角メッシュ、待機C字から直線への形状、接触補正、細線化防止を維持する。

## 2. 維持する構造と非対象

2D頭部画像・現行アホ毛PNG・毛束に沿う固定UVと三角形接続を維持する。3D化やボーン方式への全面置換は行わない。
`AHOGE_CONTACT_PRESENTATION.md` の根元固定、一回更新、基準Transform2Dの独立再構築、画面内配置を維持する。
server authoritativeなHit / Defense / Just / Clash / Round / Match / Rating、切断・復帰仕様は変更しない。SHORT投擲をLONGへ置換しない。アホ毛不在中の右クリックはDODGEのまま。

## 3. チャージ: 後方へ垂れる形状（後続実装）

C字画像全体の後方回転だけで代用せず、根元・中間部・毛先の相対位置も変える。

1. 頭部が小さく後退し、根元が頭頂部について動く。
2. 中間部が遅れて後方へたわむ。
3. 毛先がさらに遅れて後方・下方へ落ちる。
4. 長押し保持中はその形で落ち着き、時間とともに巨大化しない。

`HangBack` は0でC字、1で後方に垂れた最大溜め形状。先端接線は後方・下方を目標とする。根元を寝かせたり、頭部へめり込ませたりしない。
追加の射程伸長はしない。余白内で成立する形と配置を用意し、全体縮小だけで見切れを隠して合格にしない。

## 4. 攻撃: しなりを伝えて叩く（後続実装）

たわみが根元→中央→先端へ移動し、最後に毛先が加速して叩く動作を目標とする。
形状は `BackHang → RootLead → MidArc → TipRelease → Contact → FollowThrough → Rest` を基準にする。
等時間で全体を動かすのではなく、根元・中央・先端の前方速度ピークをこの順にずらす。
接触時には巻き込みをほどき、実メッシュの毛先と相手の表示位置の誤差2px以下、塗りと幅の保持を維持する。接触後は先端を相手へ貼り付けず振り抜く。
通常STRIKE 0.20秒／最大チャージ0.13秒／contact_ratio 0.70の時間内で検証し、演出のためにserver時間を伸ばさない。
チャージ解放時はその時の形・速度から接続し、一度C字へ戻してから攻撃しない。

## 5. パリィ: 湾曲を保つ近距離の毛先払い（今回の実装対象）

### 5.1 部位と空間

- 根元: 頭部へ固定。全体を大きく振り回さない。
- 中央: C字の曲率を維持し、先端の動きを支える。
- 先端部分: 毛束の末端側だけで短い弧を一度鋭く払う。一点の移動で折れを作らない。
- 相手の頭部へ届かせる補正、攻撃用の追加reach、全体の60度払い上げは使用しない。
- 左右は既存のfacing変換で反転する。払い方向を画面の右へ固定しない。

### 5.2 固定メッシュによる形状

既存の427頂点・680三角形・UVを変えず、毛束の弧長で末端部を識別する。画像のY座標で部位を決めない。
根元から弧長62%まではパリィ追加変位を0とし、62〜94%の区間で先端の追加曲げ角を滑らかに増やす。
区間の長さは保存し、断面は接線の変化に合わせて回す。C字を直線形へ置換するのではなく、既存の曲率へ小さい曲げを追加する。
準備・払い・反動の角度基準は +0.12 / -0.42 / +0.06 rad。全体角度ではなく、先端区間に分布する追加角度とする。

### 5.3 時間と中断

PARRY有効時間0.18秒とJust受付0.07秒はそのまま。表示のために防御開始を遅延しない。
表示進行率 0 / 0.12 / 0.52 / 0.76 / 1 に対応する先端曲げ量を 0 / 準備 / 払い / 反動 / 0 とし、滑らかにつなぐ。
頭部のきっかけは数px程度に抑え、旧パリィの大きな上下ジャンプを使わない。
攻撃中断では現在のStraightenと実際の表示transformを取得し、0.055秒で近距離の湾曲姿勢へ移る。既存の検証済みStraighten経路を逆にたどり、直線頂点からC字頂点への一括補間をしない。
パリィ直後の状態変更では残った先端曲げを0.08秒で解く。非表示・ROUND_LOCKEDは古い払いを再発させない。
通常攻撃の接触補正とパリィ表示を同時に掛けない。PARRYに入った後の古いHit通知で遠方接触姿勢へ戻さない。
成功表示と相手の反応はserverのPARRY/JUST_PARRY結果を正とし、入力だけで成功を捏造しない。

### 5.4 実装の境界

- `AhogeParryMotion`: 先端曲げの時間曲線、移行状態、弧長に沿う局所変形。
- `AhogeMeshDeformer`: 固定UV/index/RIDを維持し、攻撃形状へパリィ局所変形を適用して頂点バッファを更新。追加形状の描画境界も更新する。
- `BattleFighterVisual`: 小さい頭部運動、現在の表示からの切替、パリィ中の相手頭部追従停止。
- `AhogePrototypeRig`: パリィ中は中立の全体transformを供給し、大きな全体回転やreachを発生させない。切替の連続性はBattle側が担当する。
- 未対応素材のSprite／SHORT仮描画へ、LONG用C字メッシュを誤適用しない。

## 6. 検証・完了条件

今回追加するパリィ検査:

- 根元〜弧長62%のパリィ追加変位が0、先端に視認可能な変位がある。
- 全長と断面幅を維持し、湾曲が残る。伸長・直線化だけで代用していない。
- 固定UV/index/RID、三角形の正面積、外周の非自己交差を検査する。サンプル検査を連続全域証明とは扱わない。
- 左右・30/60/120fps・1280x720/1600x900、IDLE/CHARGING/WINDUP/STRIKEからの中断を実HUDで検査する。
- 頭部のジャンプ、遠方の頭部追従、旧Hit通知、非表示/再表示、ROUND_LOCKEDを回帰する。
- Godotで等倍再生用の連続フレームを保存する。構造・数値がPASSでも見た目の最終合格とはしない。
- 既存の攻撃接触48条件、変換の歪み蓄積防止、オンライン回帰を維持する。

後続のチャージ・ムチ打ちは§3/§4と既存要求を基準に別途実装・検証する。今回のパリィ修正を三動作すべての完了として報告しない。
Mac通常GameFlowのHuman Verificationと独立最終レビューが未完了の間は、PR #105をマージしない。
