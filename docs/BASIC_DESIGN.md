# AHOGE LEGEND 基本設計

## 1. 文書情報

- 対象プロダクト: `AHOGE LEGEND`
- 日本語呼称: アホ毛レジェンド
- 種別: ホロライブ二次創作オンライン対戦ゲーム
- 文書目的: ゲーム全体の目的、ユーザー体験、主要機能、対戦ルール、画面遷移、システム境界を定義する
- 詳細実装: `docs/DETAILED_DESIGN.md` を参照
- 画面設計: `docs/SCREEN_DESIGN.md` を参照
- ステータス: 初版
- 作成日: 2026-09-26

この文書は、2026-09-26までの企画検討とHTMLプロトタイプ検証で合意した内容を、実装前の基本設計として整理したものである。

## 2. プロダクト概要

### 2.1 コンセプト

ホロライブメンバーの「頭頂部＋アホ毛」だけが画面左右から登場し、アホ毛を武器として1対1で戦うオンライン対戦アクションゲームとする。

ゲーム画面では全身を表示せず、頭頂部とアホ毛を主役にする。見た瞬間に内容が理解できるコミカルな見た目と、攻撃・チャージ・パリィ・回避・相殺による短時間の読み合いを両立させる。

### 2.2 タイトル

正式タイトルは `AHOGE LEGEND` とする。

必要に応じて公開時の説明やロゴ周辺で `hololive fan game` などの二次創作表記を補助的に使用する。

### 2.3 主要な体験

- アホ毛の形状や動き自体をキャラクター個性として楽しめる
- マウスだけで直感的に攻撃・防御できる
- 1ラウンド85秒の短時間対戦で緊張感を維持する
- 通常攻撃とチャージ攻撃の速度差を読み合いに使う
- パリィ、ジャストパリィ、回避、ジャスト回避で防御に技量差を出す
- 同時攻撃時の相殺で偶発的ではなく視覚的に納得できる衝突を作る
- ランクマッチとフレンドマッチの双方で遊べる

## 3. 対象プラットフォーム・公開方針

### 3.1 対象プラットフォーム

- Windows 64bit: 必須対象

Steamでの公開を目標とする。

ホロライブ二次創作ゲームとして公開するため、公開時点のCOVER／holo Indie等のガイドライン・審査条件を確認し、必要な手続きを満たすことを前提とする。

### 3.3 開発・公開環境

開発・公開環境は次で確定する。

| 領域 | 採用環境 |
| --- | --- |
| ゲームエンジン | Godot 4.7.2 stable |
| ゲーム実装 | GDScript |
| 開発IDE | Godot Editor + VS Code |
| オンライン基盤 | Nakama |

オンライン対戦はNakamaを中心に構成し、PostgreSQLを永続データストアとして使用する。ローカル開発ではDocker Composeで必要なサーバー群を起動できる構成とし、本番サーバーはAWS東京リージョンへ配置する。

## 4. ゲーム画面

### 4.1 基本構図

- 左右に各プレイヤーの頭頂部とアホ毛を表示する
- 画面中央をアホ毛同士の戦闘空間とする
- 顔全体、首の断面、全身は表示しない
- 頭部そのものを前方へ突き出して距離を詰めるゲームにはしない
- 頭部は基本位置の周辺で前後・上下にモーションする
- アホ毛は頭部運動に連動した二次動作として駆動する

### 4.2 画面比率

HTMLプロトタイプでは約5:4の対戦枠と中央寄りのキャラクター配置が比較的良好だったため、本番画面の有力候補として継続する。

5:4は現時点で完全確定ではなく、実機解像度・Steamスクリーンショット・UI配置を確認して最終決定する。

## 5. 対戦形式

### 5.1 基本形式

- 1対1
- 最大3ラウンド
- 2ラウンド先取
- BO3形式

### 5.2 ラウンド制限時間

1ラウンドの制限時間は85秒とする。

タイマーは `01:25` のような分秒表記ではなく、秒単位の整数を表示する。

例:

```text
85
84
83
...
1
0
```

### 5.3 ラウンド勝利条件

通常時は、相手頭部への有効ヒット数が規定値に先に到達した側がラウンドを取得する。

実装開始時の規定ヒット数は**5ヒット**とする。これは操作感・試合時間の検証用初期値であり、Human Verificationで調整可能な設定値として扱う。

### 5.4 時間切れ

85秒経過時点で規定ヒット数に達していない場合、頭部への有効ヒット数が多い側がラウンドを取得する。

同点の場合は延長戦へ移行する。

### 5.5 延長戦

延長戦はサドンデスとし、次に有効ヒットを与えた側がラウンドを取得する。

## 6. 操作

| 入力 | 基本動作 | 状態による変化 |
| --- | --- | --- |
| 左クリック短押し | 通常攻撃 | なし |
| 左クリック長押し | チャージ | 離すとチャージ攻撃 |
| 右クリック | パリィ | アホ毛不在時は回避 |
| 攻撃中の右クリック | 防御キャンセル | 現在の防御アクションへ即時遷移 |

### 6.1 通常攻撃

- 相手が攻撃を予見できる程度の明確な予備動作を入れる
- 到達速度は速すぎず、視認して反応できる程度とする
- 連打を防ぐため攻撃後クールタイムを設ける
- チャージ攻撃よりクールタイムを短くする

### 6.2 チャージ攻撃

- 左クリック長押しでチャージする
- チャージ時間は長すぎないようにし、プロトタイプでは約0.6秒程度を目安に検証した
- 通常攻撃より明確に攻撃到達速度を速くする
- チャージ量が大きいほど攻撃後クールタイムを長くしてよい
- チャージ中はアホ毛画像そのものを拡大しない
- チャージ中は首を後ろへ引く動きに連動してアホ毛全体が後方へ傾き／張る
- 攻撃開始時に蓄えたテンションを解放し、前方へ大きく振り抜ける

### 6.3 防御キャンセル

攻撃チャージ中、予備動作中、攻撃振り出し中であっても、右クリック入力を受けた場合は現在の攻撃をキャンセルして防御アクションへ移行できる。

防御アクションはキャラクター状態によりパリィまたは回避となる。

## 7. 防御システム

### 7.1 パリィ

アホ毛を使用可能な状態では、右クリックはパリィとなる。

パリィは単なる防御姿勢ではなく、相手の攻撃アホ毛を払い上げる、またははたき落とす能動的な迎撃モーションとする。

頭部を上下に切り返し、その速度・加速度に遅れてアホ毛が追従し、相手のアホ毛を叩くように見せる。

### 7.2 ジャストパリィ

攻撃直前の適切なタイミングでパリィが成立した場合はジャストパリィとする。

効果:

- 被ダメージなし
- 攻撃側に短時間の仰け反り
- 攻撃側を短時間行動不能にする
- 通常パリィより明確な表示・エフェクトを出す

受付時間の最終値は本番の操作感試験で確定する。

### 7.3 回避

アホ毛を投擲して頭部側にアホ毛が存在しないなど、パリィ不能状態では右クリックを回避へ切り替える。

回避は頭部を素早く上下または後方へ動かして相手の攻撃をかわす。

### 7.4 ジャスト回避

回避にもジャスト判定を適用する。

- 通常回避: ノーダメージ
- ジャスト回避: ノーダメージに加えて、攻撃側へジャストパリィ同等の仰け反り・行動不能を与える

パリィと回避は防御手段が異なるが、ジャスト判定の基本概念は共通化する。

## 8. 攻撃相殺

両者の攻撃がほぼ同じタイミングで実際のヒット判定位置へ到達した場合、攻撃相殺とする。

重要点:

- マウスクリック時刻では判定しない
- 攻撃開始時刻では判定しない
- 実際の攻撃到達時刻同士を比較する

相殺時:

- 両者ノーダメージ
- 両者にジャストパリィ相当の仰け反り・行動不能
- 見た目としては両者が同時に迎撃した状態として表現する

同時と見なす時間幅の最終値はオンライン同期試験を含めて確定する。

## 9. アホ毛タイプ

アホ毛タイプは、見た目・基本駆動・しなり方の分類とする。

攻撃範囲とは別概念である。

| タイプ | 特徴 | 状況 |
| --- | --- | --- |
| 長距離型（ロング） | 長く、慣性・しなりが大きい | プロトタイプ確認済み |
| 中距離型（普通） | 標準的な長さ・取り回し | 未設計 |
| 短距離型（ショート） | 短く、素早い。投擲へ派生しやすい | プロトタイプ確認済み |

### 9.1 攻撃タイプとの分離

キャラクターの戦闘個性は、アホ毛タイプだけでは決めない。

キャラクターは次の要素を組み合わせて定義する。

```text
キャラクター
= アホ毛タイプ
+ 攻撃タイプ
+ パラメータ差
+ 固有モーション補正
```

攻撃タイプ例:

- 振る
- 突く
- 投げる
- 横薙ぎ
- 振り下ろす
- ブーメラン
- その他キャラクター固有攻撃

同じアホ毛タイプでも攻撃タイプにより攻撃速度、軌道、チャージ挙動、モーションを変える。

## 10. 頭部・アホ毛モーション

### 10.1 基本原則

マウス操作はアホ毛を直接動かす入力ではない。

処理上の因果関係は次の順とする。

```text
入力
↓
頭部・首のモーション
↓
頭部の速度・加速度・減速
↓
アホ毛の二次動作
```

アホ毛だけが独立して勝手に動いているように見せない。

### 10.2 制御付き擬似物理

完全な物理演算には拘束しない。

理由:

- キャラクターによってアホ毛の見た目長が大きく異なる
- 完全物理では相手に届かないケースが発生する
- パリィ時に見た目上接触しない可能性がある
- 攻撃判定が偶発的になり、対戦ゲームとして安定しない
- ネットワーク同期が困難になる

本番では頭部の速度・加速度を入力とし、慣性、遅れ、ばね、減衰、必要な伸縮補正を加える制御付き擬似物理を採用する。

ただし、攻撃判定・射程・相殺判定は見た目の擬似物理結果には依存させない。

### 10.3 待機

- 頭部は呼吸に合わせて軽く揺れる
- アホ毛は頭部の動きに少し遅れてゆらゆらする
- チャージ中は微細なアイドル揺れを止めて溜め姿勢を安定させる

### 10.4 ロング型攻撃

ロング型では、プロトタイプv13付近で確認した「アホ毛全体がしなりながら前方へ伸び、まっすぐに近づく」見え方を基準とする。

基本モーション:

1. 頭部を後ろへ引く
2. アホ毛が遅れて後方へ引かれる
3. 頭部を前へ勢いよく振る
4. アホ毛は一瞬後ろに残る
5. 頭部の勢いに引かれて前へ加速する
6. アホ毛全体が前方へ伸びて攻撃位置へ到達する

局所的に細かく波打たせることより、全体の前後スイング、しなり、伸縮、遅れ、振り戻しを優先する。

### 10.5 ショート型投擲

ショート型の一部攻撃タイプではアホ毛を切り離して投げる。

- 頭部を後ろへ引く
- 頭部を前へ振る
- その勢いに合わせてアホ毛を投擲する
- 飛翔中のアホ毛は視認できるサイズで表示する
- 投擲後は頭部から次のアホ毛が自然に再生する
- アホ毛不在中はパリィできず、右クリックは回避になる

## 11. オンライン対戦

### 11.1 ランクマッチ

- ランダムマッチング
- ランキングへ影響する
- 対戦前にキャラクターを選択する
- 対戦終了後に同一相手との再戦メニューは表示しない

終了後の選択肢:

- 次のランクマッチ
- キャラクター変更
- 終了

### 11.2 フレンドマッチ

ルームコードを使用して友人とマッチングする。

ランキングには影響させない。

終了後の選択肢:

- 再戦
- キャラクター変更
- 終了

### 11.3 ランキング

ランキングは月単位のシーズン制とし、毎月ランキングをリセットする。

ランキングは次の2種類を持つ。

#### プレイヤーランキング

個々のプレイヤーのランクマッチ成績を対象とする。

- プレイヤー単位で集計する
- Ratingおよびランク帯を持つ
- ランクマッチのみを集計対象とする
- フレンドマッチは対象外とする
- 毎月1日0:00（日本時間/JST）に新シーズンへ切り替え、当月ランキングをリセットする
- 実装開始時はElo方式を使用し、初期Rating 1500、K値32とする
- 暫定Elo期待勝率は `1 / (1 + 10 ^ ((opponent - self) / 400))` とする
- Rating更新値は四捨五入して整数とする
- Round境界15秒timeoutはMatch強制敗北ではなく、そのRoundの不戦敗として処理し、最終的に通常BO3で2本先取したMatch結果をRating更新対象とする
- Friend Match、server障害、両者同時切断はRating更新対象外とする
- ランク帯は仮定値として Bronze / Silver / Gold / Platinum / Diamond / Master を使用する
- 月次シーズン開始時は全プレイヤーの当月Ratingを1500から開始する
- Rating・ランク帯境界は運用データを見て調整可能とする

#### AHOGE LEGENDランキング

キャラクター（アホ毛）ごとの全プレイヤー合算勝利数を競うランキングとする。

順位決定値は、対象月のランクマッチにおける**総マッチ勝利数**とする。

```text
キャラクターAを使った全プレイヤーの当月ランクマッチ勝利数
= キャラクターAのAHOGE LEGENDランキング集計値
```

重要なルール:

- 個人ごとのキャラクター勝利数ランキングではない
- そのアホ毛を使用した全プレイヤーの勝利数を合算する
- 1マッチ勝利につき、勝者が使用していたキャラクターへ1勝を加算する
- ラウンド勝利数は加算しない
- フレンドマッチは集計対象外とする
- 毎月1日0:00（日本時間/JST）に当月集計値を0から開始する
- 使用回数や勝率は順位決定には使用しない
- 1位のアホ毛を、その月の「伝説のアホ毛」として扱える表示・演出を行う

これにより、プレイヤー自身の強さを競うランキングと、全プレイヤーが力を合わせてどのアホ毛を最も勝たせたかを競うランキングを並立させる。

前月以前のランキング結果は履歴として保持し、当月ランキングの集計値とは分離する。

ランキングの月替わり境界は毎月1日0:00（日本時間/JST、UTC+9）とする。Rating算出方式、ランク帯、マッチング検索幅は未決とする。

勝敗・ランキング更新はクライアント任せにせず、Nakama側のサーバー権威で確定する。

## 12. 対戦前後の演出

### 12.1 対戦前

マッチング成立後、両キャラクターの短い掛け合いを表示する。

- ボイスなし
- テキストのみ
- 対戦テンポを損なわない短さ
- 汎用台詞と特定組み合わせ専用台詞を持てる構造が望ましい

### 12.2 勝利後

勝者キャラクターが一言の煽り／軽口セリフを表示する。

- ボイスなし
- 本気の侮辱ではなく、コミカル・プロレス的な軽口を基本とする

## 15. アート・素材

### 15.1 画像素材

- 本番ではゲーム用の頭頂部・アホ毛素材を新規に描き起こす
- 頭部とアホ毛を別パーツ化する
- 必要に応じて追加の変形・マスク・リグ用パーツへ分割する
- Live2Dのように滑らかに駆動する見え方を目指す
- HTMLプロトタイプで生成したPNGは検証素材であり、本番素材として扱わない
- 既存公式画像の単純切り抜きは本番素材として使用しない
- holo Indie等から公式に利用可能な素材提供を受けられる場合でも、差し替え可能なアセット構造を維持する

### 15.2 音声・SE素材

攻撃、被弾、パリィ、勝利演出などで、ホロライブメンバーの配信内発言を短い音声素材として利用する案を許容する。

ただし、公開配信から切り出した音声が自動的にゲーム利用可能であるとは扱わない。

配信音声を候補素材として扱う場合は、少なくとも次を記録する。

- タレント名
- 元配信URL
- 元配信タイトル
- タイムスタンプ
- 切り出した発言内容
- ゲーム内での用途
- 使用可否の確認状態
- 確認根拠または許諾元

使用可否の確認状態が未確認の素材は、本番採用済み素材として扱わない。

holo Indie等から公式提供された音声・SE・素材がある場合は、提供条件に従って使用し、出典・提供元・利用条件を記録する。

対戦前の掛け合いと勝利後の軽口セリフは、現在の基本仕様どおりボイスなしのテキスト表示とする。配信切り抜き音声は必須要素ではなく、使用可能な場合の追加演出として扱う。

## 16. プロトタイプで確認した事項

- 頭頂部＋アホ毛だけでも対戦画面として成立する
- ロング型とショート型で大きく異なる攻撃表現を持たせられる
- ショート投擲型では、攻撃中の防御手段をパリィから回避へ変えることが自然
- 通常攻撃・チャージ・防御キャンセルの組み合わせで読み合いを作れる
- 同時攻撃は入力時刻ではなくヒット到達時刻で相殺判定するのが自然
- PNGを頭部・アホ毛の別レイヤーとして扱う方式は本番のパーツ構成検討に有効
- 細かなプロトタイプの秒数・ばね定数・回転量は本番値として固定しない

## 17. 非機能要件の基本方針

### 17.1 操作レスポンス

マウス入力からゲームロジックの受付まで不必要な遅延を発生させない。

オンラインでは通信遅延が存在しても、ローカルのモーション表示が不自然に停止しない設計を目指す。

### 17.2 ネットワーク公平性

- 勝敗・ランキングに関わる結果をクライアント単独で確定しない
- 見た目と判定の分離を維持する
- 同時攻撃やジャスト判定は通信遅延を考慮した設計が必要

### 17.3 対象環境

Windowsを基準環境とする。

macOS対応を行う場合も、ゲームルールやコンテンツ実装がOS依存にならない構成とする。

## 18. 実装開始時の暫定基準

未確定だった実装ブロッカーは、最初の縦切り実装を開始するため次の仮定値で進める。

- Godot: 4.7.2 stable
- 初期対戦キャラクター: 実在タレントを確定せず、ロング型1体とショート投擲型1体の仮キャラクター
- 1ラウンド勝利条件: 5ヒット
- クライアント描画目標: 60fps
- Nakama authoritative match tick: 30Hz
- 通常攻撃Windup: 0.18秒
- 通常攻撃Strike: 0.20秒
- 通常攻撃Cooldown: 0.48秒
- 最大チャージ時間: 0.60秒
- 最大チャージ攻撃のRelease Windup: 0.08秒
- 最大チャージ攻撃Strike: 0.13秒
- 最大チャージ攻撃Cooldown: 0.82秒
- パリィ有効時間: 0.18秒
- ジャストパリィ時間: 0.07秒
- 回避有効時間: 0.22秒
- ジャスト回避時間: 0.07秒
- 攻撃相殺許容差: 0.067秒
- Stagger: 0.45秒
- ショート投擲のアホ毛再生時間: 0.60秒
- 初期ネットワーク方針: rollbackなし、Nakamaサーバー権威、入力にsequence番号を付与
- Round進行中の片側切断: 試合全体は停止せず、接続中の側・85秒timer・戦闘・Overtimeは継続する
- Round進行中は切断からの経過時間に関係なく、同じRoundが終了するまで再接続を許可する
- 切断側: 新しい入力は停止するが、serverが切断前に受理済みのaction stateはauthoritative tickで進行する
- 同じRound中に復帰した場合: server authoritative snapshotへ同期し、その時点のRoundを継続する
- Round終了後の片側切断: 前Round Result表示を先に完了し、その表示時間中は15秒を消費しない
- Result表示完了後に次Round開始側へ切り替え、相手が未接続ならそこで15秒の復帰待機を開始する
- Round開始前 / Countdown中の片側切断: その対象Roundの開始側で15秒の復帰待機を開始する
- Round境界の15秒以内に復帰した場合: snapshot同期後に対象Roundへ進む
- Round境界の15秒以内に復帰しない場合: その対象Roundだけを切断playerの不戦敗、接続中playerの不戦勝としてRound取得数へ反映する
- 不戦勝を加算して2本先取になれば通常BO3としてMatch終了する
- 不戦勝を加算しても2本先取でなければ、次Roundについて改めて15秒の復帰待機を開始する
- active Round中の切断では通常の5 Hit / 85秒Hit数比較 / OvertimeでRound勝敗を決め、切断中playerが通常ルールで2本目を取った場合もそのMatch Winを有効とする
- 再接続成功時: server authoritative snapshotを受信し、復帰時点の状態へ同期する
- 対戦中のゲーム終了 / client再起動後も、再ログイン時にNakama user_id単位のserver-side active matchへ復帰を試みる
- 対戦join後は「未解決の対戦」としてlockし、Battle復帰または終了後遷移が確定するまで新しいRanked / Friend対戦を開始できない
- 同一プロセス内のSocket切断と再ログイン後の復帰は同じ未解決match復帰契約を使用する
- 15秒はactive Round中にも前Round Result表示中にも開始せず、Result表示完了後に次Round開始側へ切り替えた時点、またはRound開始前 / Countdown中に未接続playerがいる場合に開始する
- Round境界15秒timeoutで不戦敗Roundが成立した後もMatch未決着なら同じ未解決matchを維持し、次Roundの復帰待機へ進む
- 不戦敗Roundを含む通常BO3でMatchが終了した後は、回線復旧時にserver-side RESULT_PENDINGから終了済みResultを取得する
- 再ログイン時にmatchが進行中ならBattleへ復帰する
- 再ログイン時にRanked matchが終了済みならBattleを再表示せず、authoritative結果をUI-11へ表示する
- 再ログイン時にFriend matchが終了済みなら結果画面を再表示せず、Character Select（選択メニュー）へ戻す
- フレンドルームコード: 6文字
- プレイヤーRating初期値: 1500
- Elo K値: 32

これらは完成仕様ではなく、コードへ直接散在させず設定値として一元管理する。
操作感・負荷・通信試験の結果で変更する場合は設計値も同期して更新する。
