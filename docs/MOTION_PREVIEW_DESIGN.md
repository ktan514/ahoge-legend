# ロングモーションの手動調整・オフラインプレビュー

関連: #102 / PR #105。基準コード: `9aacec86b752d2d3ab715ae4b4bb57a20f12ff26`。

## 目的と範囲

人間さんが自分でコードを編集し、再生・停止・コマ送りで結果を確かめるための開発専用ツール。初版は表示だけを目的としていたが、2026-10-06以降はNeckRangePreviewで調整する「アホ毛柔らかさ」を同じBattleFighterVisualへ渡し、通常Battleと同じ柔軟chainを確認する正規の調整導線とする。サーバー判定は変更しない。
従来の通常GameFlow方針は製品起動と最終Human Verificationへ維持する。今回明示された簡易確認ツールは `tools/motion_preview/` の開発専用Sceneとし、Top Menuや通常起動へ接続しない。

## 再利用と隔離

- 実際の `BattleHUD.tscn`、`BattleContactDirector`、`BattleFighterVisual`、`AhogeActionMotion`、固定メッシュをそのまま使用する。JavaScript等へ動作式を複製しない。
- 同一プロセス内でLONGと相手を描画する。Nakamaの起動、認証、P2の別起動、マッチング、Rating更新は行わない。
- ActionStateの入力列だけをツールが供給する。ContactDirectorを自動更新から外し、シミュレーション時間で明示的に一度ずつ進める。
- これは表示検証であり、対戦判定・通信遅延・オンラインのパリィ成功を再現したものではない。HUD内のスコアを実戦の結果と誤認させない表示を置く。

## 操作

通常攻撃、チャージ攻撃、溜め保持、パリィ、攻撃からパリィへの中断を選べる。左右、相手LONG/SHORT、チャージ量、描画解像度に加え、アホ毛柔らかさ0.0〜1.0を切り替える。柔らかさはNeckRangePreviewと同じ値を同じBattleFighterVisualへ渡し、別実装・別係数を持たない。
再生/停止、先頭へ戻る、前後1コマ、時間スライダー、接触時刻への移動、0.1/0.25/0.5/1倍速を用意する。コマの間隔は選択した30/60/120fpsで決まる。
逆送り・シークは状態変数を逆算せず、HUDを再生成して先頭から同じ入力列を進め直す。同じ設定・時刻で同じ頂点位置になることを検査する。
表示用のSubViewportは1280x720または1600x900とし、ウィンドウ内ではアスペクト比を保持して縮小表示する。HUDへ解像度を二重に加算しない。
オプションで中心線、毛先の軌跡、三角メッシュを重ねる。保存するスクリーンショットはこのプレビューの画像であり実機対戦録画ではない。

## コード編集と再読み込み

調整値は本体の既存ソースをVS Code/Godot Editorで編集する。ツールはソース・設計書を自動上書きしない。constの変更は既存インスタンスへ反映されないため、コード保存後にツールを再起動する。再読み込みボタンは同じGodot実行ファイルで開発Sceneを新規起動してから旧ツールを閉じる。失敗時は旧ツールを維持し手動再起動を案内する。
形状・時間・接触補正は別責務として操作ガイドへ一覧化する。調整した製品コードの変更時には仕様ドキュメントも更新する。

## 検証

- 新規Sceneのimport・構文・実描画と操作信号。
- シナリオ、左右、2解像度、シーク再現性、接触2px以下、PNG保存。
- 柔らかさ0.0/1.0でSTRIKE中の実頂点に明確な差が出ること。選択値が再build・再読込後も保持されること。
- ツールのみを起動して認証・Realtime接続・対戦参加が発生しない。
- モーション本体の既存ファイルが変更されていないことを差分で確認する。
- ツールの再生結果をオンライン統合・MacのHuman Verification・モーション品質合格の代わりにしない。
